# Rules

## Purpose
Durable constraints agents should follow while doing other work.

## What Belongs Here
Coding standards, testing rules, security rules, review expectations, and language-specific conventions.

## What Does Not Belong Here
Step-by-step task workflows or project-specific architecture.

## Portability
Rendered into guidance files or target-specific rules folders.

## Provenance
Rules are custom unless noted in `registry.yaml`.

## Install Behavior
Rendered into guidance files in v0.1.

## Examples
`security.md`, `testing.md`, `code-review.md`.
