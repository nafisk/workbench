# Specs

## Purpose
Kiro-like spec-driven development templates and workflows.

## What Belongs Here
Requirements, design, task, verification, and state templates; reusable spec workflow instructions.

## What Does Not Belong Here
Active project specs from a product repository.

## Portability
Plain Markdown and YAML files work across tools. The orchestration behavior is implemented through skills and commands.

## Provenance
Templates are custom unless noted in `registry.yaml`.

## Install Behavior
Copy into project repositories when the spec-driven profile is attached.

## Examples
`templates/requirements.md`, `templates/design.md`, `templates/tasks.md`, `templates/state.yaml`.
